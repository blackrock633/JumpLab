# Data, privacy and retention

JumpLab processes videos on the phone using AVFoundation and Apple Vision. It has no cloud-video endpoint, storage bucket, analytics SDK, chatbot or paid inference API. Video frames and images are never intentionally sent over the app's network client. A runtime interception check has not yet been performed.

PHPicker copies the selected video to a disposable local cache. Copies are attempted to be removed after success, failure, cancellation, navigation or the next app-module startup. iOS can remove caches at any time; a picker URL is never treated as permanent. Cleanup failures can leave a cache copy until a later cleanup or uninstall. Source Photos media remains under your control and is not deleted. Saved estimates reopen from timing metadata and contact evidence. Before native analysis returns, an atomic receipt stores decoded timestamps and detected transitions with stable result IDs. The account-scoped receipt is protected while the device is locked and excluded from backups. On reopening, the app validates and saves any unfinished receipt, then clears it. Logout and account changes erase prior-account receipts.

Local SQLite stores profile answers, plans/prescriptions, workout progress, estimated jumps, and a small pending-write queue. Metadata includes body weight, limitations/pain, feedback, timing provenance and event evidence; it is private account data. SQLite is in the app's Documents/SQLite area and can be included in OS-managed backups. Tokens and PKCE state use Keychain-backed SecureStore, restricted to this device while unlocked. No app-level encrypted SQLite or comprehensive forensic-erasure guarantee is claimed. Device passcode and OS protections matter.

Only the configured Supabase project receives authentication requests and JSON metadata. The publishable key is public; ownership is enforced by JWT identity/RLS and trusted RPCs. Pending records remain on this device until you explicitly refresh/retry, resolve a conflict, delete the account, or confirm sign-out erasure. There is no polling or background generic sync service. Offline analysis and cached workouts do not require network; Debug builds may still require Metro to launch their JavaScript.

Sign-out/account switch deletes cached private records and pending writes, checkpoints and vacuums SQLite. Sign-out explicitly warns before discarding unsynced changes. This app does not support retaining an A-account queue while B is active. Uninstall removes the app container, but iOS Keychain entries may outlive an uninstall; signing out first removes app session keys. Backups or provider retention can outlive local erasure.

Account deletion calls a trusted authenticated database function, removes the Auth user and cascades all application and limiter rows, then clears local private storage and the Keychain session. The app stores deletion progress and retries failed cleanup on restart. An unexpired owner JWT can retry the same deletion after a lost reply. After that JWT expires, if the service cannot confirm deletion, the app offers local erasure with an explicit cloud confirmation warning. Previously minted access tokens may remain cryptographically valid until expiry (configured 15 minutes), but RLS and mutation RPCs check that the Auth account still exists, preventing access/resurrection. Refresh tokens should fail after account deletion; real backend tests remain required. Other signed-in devices may retain offline caches until they reconnect/clear local data; remote deletion cannot erase a disconnected phone. Supabase backups, infrastructure/Auth/security logs and email-provider retention follow the configured providers' policies. Verify and publish actual project/provider retention before public use; no exact provider deletion period has been established here.

Application source contains no telemetry or content log sinks. User-facing errors avoid raw Auth/backend responses. Evaluation/test tools log test labels and non-secret metrics, never tokens or videos. Evaluation artifacts may contain local fixture filenames and annotation IDs and should be kept private. Source pattern scanning cannot prove absence of secrets in future compiled assets or provider logs. Do not put privileged keys in `EXPO_PUBLIC_*`, commit `.env`, or print seeded sensitive values during device checks.
